# Implementation status — v0.6.2

A separate release-only distribution workflow builds one per-user Windows NSIS installer with native x64/ARM64 payloads and bundled Electron runtimes. It does not require application frameworks on the destination computer, request elevation, auto-launch the app, or force-close a running control session. The working development package remains untouched. See [distribution](DISTRIBUTION.md) for rebuild/install instructions and deployment-validation limits.

Pitot integration identifies the inspected Marlin controller, automatically homes X/Y on startup connection, and provides Home Pitot, Move Pitot and Stop Pitot controls. Both axes now allow 0–360 mm without swapping, per the operator's clarification of conflicting axis limits. The 30-second homing invalidation was removed: successful homing persists through idle time and tab changes. Runtime M84 S0 preserves motor holding while idle. USB loss, reset/error, stop and failed motion still invalidate homing. Moves slow to 5 mm/s within 5 mm of either configured end and use distance-based completion deadlines; normal interior feed remains 4000 mm/min. Global Emergency Stop also sends Pitot M112. No firmware, EEPROM or original LabVIEW files were changed. Operator-confirmed live motion remains the earlier slow homing and 2 mm horizontal test; this update is tested offline. See [evidence](PITOT-2026-11-19.md).

This release is a binary, board-only application. It opens on Main, suggests a DAQ by USB identity in Hardware and requires explicit DAQ connection. No simulation mode, generated data source or ASCII selector is available. Pitot target editing is local until Move; the Pitot connection and homing flow are independent of DAQ acquisition.

Available: Main, Pitot, Force Balance, selectable raw sensor graphs, 24-channel Pressure Array, Data Viewer, calibration/tare, recording/CSV and Hardware. All five binary banks/37 slots, raw monitoring, timestamps/rollover, invalid/stale quality and reconnect are supported. The effective atmospheric display bridges invalid samples using a labeled last-valid value for at most two seconds; raw logs keep all NaNs. UI snapshots publish at 10 Hz and derived airspeed waits two seconds after sensor startup.

Manual fan output maps 0–100% to 0–3.000 V DAC before amplification. Apply is explicit and board acknowledgment is required. The Rev Run confirmation box, popup, lock controls and underlying readiness state/action are removed. Fan output is available directly after connection and DAC-zero verification. The app does not attempt to infer VFD run state. Acquisition remains connected when fan initialization fails, provided USB is healthy. Startup, Stop, Emergency Stop, normal disconnect and exit request zero. Pending nonzero commands are canceled by Stop and cannot transfer across reconnects. Reset never resumes output. Physical fan operation was confirmed only in a supervised 0–150 mV test. Full-range output is tested offline; calibrated airspeed control and PID remain uncommissioned.

For derived speed, differential pressure from −3 to zero Pa is treated as zero; values below −3 Pa remain flagged. Original pressure values/NaNs and recordings are preserved.

Firmware remains unchanged, including the identified KP467 diagnosis-bit defect. CH340/Pitot ports remain excluded. The November 18 production-app zero-output check confirms effective atmospheric display availability in 99 of 100 checks despite 53 raw NaN snapshots. Subsequent development uses saved data after the user disconnected the board. Older dated capture reports describe earlier releases and mode options.
