## App behavior

Every startup attempts one Pitot connection independently of the DAQ. A single CH340 candidate is required; M115 must match machine name, UUID and emergency parser before motion. Each new connection restores the captured original RAM limits, checks steps/mm/offsets/software endstops and presence of both switch reports, then homes X followed by Y at native firmware homing speed. It never sends bare G28 or any Z move. Each homing command has a fixed 15-second deadline. Failure requests M112 when motion may be active and latches a fault; it cannot silently proceed to Y or a target.

As of v0.6.1, Home Pitot repeats initialization/homing and Move accepts absolute X/Y in **0–360 mm on both axes, without swapping**. The operator initially cited LabVIEW X400/Y360, which conflicts with the captured native X360/Y400 limits, then explicitly selected 360 mm for both until testing identifies the larger axis. Native firmware software endstops remain enabled and unchanged.

Successful homing now lasts for the connection. The v0.6.0 30-second idle invalidation was removed; snapshots and tab changes never clear homing. Runtime `M84 S0` disables the motor inactivity timeout so motor holding is retained; this is not bare M84/motor release and is not saved to EEPROM. That timeout setting remains in RAM until restart. USB loss, reset/error, stop and failed motion still invalidate position. Home is also available manually. The host does not deliberately release the vertical carriage when disconnecting.

The straight-line target path is split at 5 mm end-zone boundaries. Moving axes travel at 300 mm/min near either limit, returning to 4000 mm/min in the interior. An axis held stationary at home does not slow a long move of the other axis. Each segment waits for M400 plus matching M114; the deadline is distance/feed plus three seconds, with a five-second minimum, rather than the old fixed five seconds that would time out on a full diagonal. The renderer cannot send raw G-code. Overlapping actions are rejected. Stop Pitot bypasses normal waits with M112; a power cycle, reconnect and home are required after stop. No M999 or automatic resume is issued, and no later segment is sent after a fault or stop.

The original LabVIEW command omitted F and inherited the active firmware feedrate. No exact numeric feed was found in the VI or notes. Normal app target moves explicitly use the [upstream Marlin default](https://github.com/MarlinFirmware/Marlin/blob/bugfix-2.1.x/Marlin/src/module/motion.cpp) of 4000 mm/min (66.7 mm/s), removing the test's inherited F60. This is a reproducible choice, not a measurement of the deployed LabVIEW feedrate. Native homing uses the installed firmware's own homing feedrate. RAM changes are not persisted with M500, and no M502 settings reset occurs.

The UI labels completed position as Marlin-reported/open-loop. Neither an `ok` nor step counts prove the carriage physically moved. The host target bounds do not limit native G28 homing search/back-off; functioning minimum switches and clear homing paths remain necessary. Full-travel planning is tested offline; faster/full-range live motion, scan paths and synchronized spatial sampling have not been physically tested by this update. The operator will check which axis can exceed 360 mm later. Pitot transcript is displayed separately; DAQ CSV columns remain measurement channels only.

## Reproduction

`scripts/inspect-pitot.cjs` is read-only identification. `scripts/commission-pitot.cjs` is a manually invoked, fixed-phase slow commissioning helper, not part of automatic app operation. Do not use it to benchmark normal app speed. It leaves the slow caps in RAM; the app restores the captured original values on connect. Neither script uploads firmware. Unit tests replay the saved identification/settings and adversarial serial fixtures. Desktop tests disable real startup discovery with `WT_DISABLE_PITOT_DISCOVERY=1` and inject fixtures before connecting through the production UI. That environment variable only disables automatic discovery; it enables no simulator or extra control command.
